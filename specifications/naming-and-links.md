# 命名、ID 与链接规范

## 1. 目录命名

- 顶层和系统目录使用英文小写，避免跨平台编码和脚本歧义。
- 已确定的顶层目录不要随主题变化。
- 不建立深层主题目录；主题通过链接、属性和 MOC 管理。
- Yanki 监控区例外：其子目录直接表达 Anki Deck 层级。

## 2. 文件命名

人工笔记推荐：

```text
<id>--<可读标题>.md
```

例如：

```text
20260725-143210-k4p9--记忆与理解的区别.md
```

优点：

- ID 防止同名冲突。
- 标题便于搜索和文件浏览。
- 标题变化时仍可通过 frontmatter `id` 识别身份。

捕获型 Source 在未知正式标题时仅使用 `<source-id>.md`。完成处理后统一重命名为：

```text
<作者>--<正式标题>--<YYYY-MM-DD>--<source-id>.md
```

捕获流程管理的一对一 Annotation 汇总文件使用：

```text
annotated_<作者>--<正式标题>--<YYYY-MM-DD>--<source-id>.md
```

作者按正式署名、出版者/账号/组织/站点、URL 域名、`未知作者` 的顺序回退；多个作者以 `、` 连接。日期取 Source 的 `captured` 本地日期。作者与标题文件名部分分别最多保留 32 与 80 字符，frontmatter 始终保留完整值。

捕获型 Source 把 `source_id` 保存为 alias，关系链接使用 `[[<source-id>|<正式标题>]]`，使临时文件重命名不破坏链接。Annotation 仍保留独立 frontmatter `id`，但上述一对一汇总文件以 `source_id` 命名。

避免使用：

```text
< > : " / \ | ? *
```

也避免只改变大小写的文件名，防止 Windows 与 Linux 行为不一致。

## 3. 永久 ID

格式：

```text
YYYYMMDD-HHMMSS-xxxx
```

规则：

- 创建后永不改变。
- 自动化必须在写入前生成。
- `xxxx` 为随机后缀，防止同秒创建冲突。
- 除捕获流程管理的一对一 Annotation 汇总文件外，文件名与属性 `id` 应一致。
- Yanki `noteId` 是外部绑定字段，不是 Vault ID。

## 4. 内部链接

### 4.1 属性关系

```yaml
source: "[[20260725-143210-k4p9--文章标题]]"
derived_from:
  - "[[20260725-151022-m7x2--文章批注]]"
related:
  - "[[20260726-090100-p2q4--另一个观点]]"
```

Source 关系必须同时保留：

```yaml
source_id: 20260725-143210-k4p9
source_title: 文章标题
source_url: https://example.com/article
```

这是有意保留的少量冗余：即使文件重命名或链接损坏，批注仍可识别来源。

### 4.2 正文链接

- 用 `[[笔记]]` 表达真正的语义关系。
- 不为每个名词建链接。
- 链接附近写明关系，例如“反例”“前提”“进一步推论”，不要只堆链接。

推荐：

```markdown
这一判断依赖于 [[间隔效应并不等同于理解]] 中区分的两种记忆任务。
```

不推荐：

```markdown
相关：[[记忆]] [[学习]] [[理解]] [[知识]]
```

## 5. 引用定位

优先级：

1. 标题或小节：`[[来源#某一节]]`
2. PDF 页码：Zotero URI 或 `[[文档.pdf#page=12]]`
3. transcript 时间戳：`[[来源#00：13：42 记忆与理解]]`
4. 块 ID：`[[来源#^quote-id]]`

块 ID 是 Obsidian 扩展，只用于需要精确段落定位的场景；任何块引用都必须同时复制引文文本。

统一引用单元：

```markdown
> 引文原文。

来源：[[来源#对应章节]] · [外部原文](https://example.com)

我的评论：
```

PDF：

```markdown
> 论文原文摘录。

来源：[[论文来源记录]] · 第 12 页 · [在 Zotero 打开](zotero://open-pdf/...)

我的评论：
```

Transcript：

```markdown
> 说话者原话。

来源：[[访谈 transcript#00：13：42]] · 00:13:42

我的评论：
```

## 6. MOC

MOC 的 `type` 为 `map`。一个 MOC 应包含：

- 当前专题的核心问题。
- 已形成的主要判断。
- 观点之间的关系。
- 关键来源与推荐阅读次序。
- 未解决问题。

MOC 不是自动链接清单；它是人工维护的导航与结构说明。

## 7. 标签

标签只用于轻量横向标记，例如：

- `needs-verification`
- `favorite`
- `sensitive`
- `anki-source`

抓取、阅读、成熟度和类型均已有独立属性，不再重复编码为标签。
